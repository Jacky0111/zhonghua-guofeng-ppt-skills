# 中国美学风格导入工作流

当用户提供一种新的中国美学风格名称并希望筹备或创建对应设计 Skill 时使用。用户只给出风格名称也足以启动：调查风格背景，提出设计方向，生成五张预览并交由用户审核。除非用户主动要求，不要要求用户再次解释本文件中的统一规范。

## 必须遵守的边界

- **人工审核是不可跳过的实施门槛。** 新风格首次运行时，完成调查、方案和五张预览后，展示结果并等待用户明确确认。沉默、继续讨论或只说“继续”而未批准视觉方向，不等于确认。用户要求修改时先迭代预览；不得提前创建正式 `SKILL.md`、归档为正式资源或更新发行目录。
- 仅在用户明确批准当前预览方向后进入正式实施。若用户在另一轮明确批准，按已批准方向继续，无须重复索取确认。
- 统一可复用的设计语言和判断原则，不统一页面模板。布局、组件、比例和信息密度由内容决定；预览页数及封面、内容页、结束页角色按本工作流明确规定执行。
- 参考图用于理解色彩、材质、纹理、光泽、视觉层级和审美节奏，不复刻整页构图或文案。陶瓷风格默认表达材质感，不要求绘制器物。
- 国风设计追求“神似而非形似”。从参考对象中提炼色调、材质、抽象纹理、光泽、疏密、留白、线条节奏和艺术气质，再用现代排版表达；不因器物上出现花卉、龙凤、山水等具象装饰就直接复制到 PPT。仅当用户内容确实讨论该图案，或具象图像对理解不可替代时，才有目的地使用并注明出处。
- 所有史实、配色出处和资源均记录来源及授权状态；相对路径引用，不得依赖个人电脑路径。
- 按本仓库贡献指南、项目说明（如有）、资源索引和发行结构执行；遵循其中已有规范，不在本 Skill 中另造冲突规则。

## 工作阶段

### 1. 调查历史与视觉证据

先查看仓库现有 Skill、分类、资源索引和发行结构，确认风格 ID 是否已存在，避免重复创建。使用可靠的第一手馆藏、考古/研究机构或原始文献调查：历史渊源、地域与时期、文化背景、材料工艺、核心色彩、质地纹理、装饰特征及其差异。对可能变化或有争议的资料使用联网检索核验。

记录三类结论：**已核实事实、合理推断、未知/争议**。区分历史证据与现代视觉解释，尤其不要把某件器物的特征推广为整个窑口/时期的定律。

### 2. 头脑风暴并提出设计方案

围绕该风格探索若干可区分的方向，再给出推荐方向及依据、取舍与不确定性。方案须覆盖：

- 色彩体系及主次关系；
- 材质、纹理、光泽、渐变和自然变化；
- 字体气质、字号层级、留白与阅读节奏；
- 背景、抽象纹理、装饰节奏及其使用边界；如保留具象纹样，须说明内容必要性和来源；
- 图表、表格、时间轴、卡片和插图如何随信息关系变化；
- 风格特征如何进入整页系统，同时保持内容可读。

说明哪些是史实依据，哪些是现代转译。避免以颜色替换作为唯一风格区分，也避免把具象传统纹样当作国风捷径；根据内容灵活安排布局，不规定固定版式。

### 3. 生成五张视觉预览

围绕同一主题生成**恰好 5 张彼此独立**的 PPT 页面效果图，不合并成拼图。五张必须包括 1 张封面（Cover）、3 张根据主题内容灵活确定的内容页，以及 1 张结束页（Ending）。Cover 和 Ending 指页面在叙事中的角色，不规定固定版式；其余三页应展现有差异的内容布局。五页文案简洁、由内容驱动，同时共享同一设计语言。以色彩、材质、抽象纹理、光泽和视觉节奏提炼风格，不直接搬用器物上的花卉、龙凤、山水等具象纹样，除非内容本身需要讨论该图案。检查风格是否融入背景、文字区和组件；不要只把质感放在孤立装饰图中。

使用可用的 `imagegen` 能力生成图像；需要真实幻灯片文件时才使用 `presentations` 工作流，本阶段默认不生成 PPT/PPTX。将预览暂存于 `visual-previews/<stable-style-id>/`，并说明它们是设计示意，不是文物图、最终模板或已获发布授权的素材。

### 4. 人工审核与迭代【强制停点】

逐张检查文字、史实边界、封面/结束页是否齐全、三张内容页的布局差异、风格辨识度、整体一致性、可读性，以及是否把参考对象上的具象图案直接拼贴到页面。特别检查正文、小字和标注在纹理、光晕及高亮背景上的对比度；必要时增加稳定的文字底色或调整纹理强度。向用户展示五张预览、简要说明设计取舍，并明确询问是否确认方向。

- 若用户提出修改：按反馈更新方案或对应图像，再展示待审版本；维持预览阶段。
- 若用户明确批准：进入阶段 5。
- 若批准范围不清楚：继续等待澄清，不推断批准。

**到达此停点后必须结束本轮实施工作。** 不得以减少流程、时间或自动化为由跳过人工审核。

### 5. 按确认方向创建正式风格 Skill

仅在审核通过后实施：

1. 使用稳定、机器可识别的英文 kebab-case ID；建立中英文两份发行包，采用经验证的汝窑目录形态：`.agents/skills/<skill-id>/SKILL.md`、`agents/openai.yaml`、`assets/README.md`，仅在实际需要时添加 `assets/examples/` 与 `references/`。
2. 编写简洁的 `SKILL.md`，说明触发场景、独立设计语言、自适应构图规则、阅读参考资源的方法及不得复刻示例版式的边界。保持已有核心原则：内容驱动设计、风格一致而非模板重复。每个包的 `SKILL.md` 末尾须原样附上对应语言的多语言章节：中文包用 `references/multilingual-section.zh-CN.md`，英文包用 `references/multilingual-section.en.md`。
3. 将**已审核并批准归档**的预览复制到 `assets/examples/`；补充适用场景、来源/生成方式、审核状态、权利状态和使用限制。若引用原始外部图片，记录出处及授权；权利未清楚时标记 `local-only` 或 `review-required`，不得声明可公开发布。
4. 资源引用全部相对于 Skill 目录。按贡献指南同步 `VERSION`、`catalog/`、分类、README 页眉与版本表、`CHANGELOG.md`；多语言规则有改动时同步全部 Skill、`DESIGN-PRINCIPLES.md` 与上述两份章节文件；保持两边稳定 ID、版本、功能、文件结构与二进制资源一致，分别专业本地化说明文字。
5. 按仓库惯例更新安装器/目录和资源索引。正式归档后删除同一工作区内重复的临时预览副本；不要删除有独立对照用途的来源快照。

### 6. 验证 Clone、调用和发布门槛

运行现有校验工具；检查 frontmatter 与 `agents/openai.yaml`、目录/分类/版本一致性、所有相对路径和 Markdown 链接、示例文件存在性、双语资源哈希、安装器及显式调用 ID。将发行目录复制/克隆到干净临时位置，确认 Skill 可安装并能访问其图片资源。若权利/许可证仍未清楚，发布模式应失败并列出阻断项。

更新目录、资源索引、双语 README、贡献文档或发布清单中与新增包直接相关的内容。不得仅因 Skill 完成而创建 GitHub 仓库、选择许可证或推送；这些动作须遵守仓库设置批准门槛。

## 完成汇报

向用户简要汇报调查结论与不确定性、推荐设计方向、五张预览位置或正式包路径、审核状态、同步/验证结果，以及仍阻止公开发布的素材或仓库设置。未获审核批准时，明确标为“预览阶段，未创建正式 Skill”。

## 多语言生成

本节优先于本 Skill 中任何与语言、字体或阅读方向有关的表述。

- **指令语言不等于输出语言：** 本文件用中文撰写，不限定演示文稿的语言。
- **自动决定输出语言：** 用户指定时按指定执行；否则依据用户本次输入的语言与意图自动判断（页面内容、请求措辞、上下文），不固定为任何语言，也不以仓库或指令语言为默认。支持任意语言及多语言混合。
- **原文不可擅改：** 不得擅自翻译、改写、简繁转换或转写用户提供的内容（含专名、引文、代码、数字与单位）。仅在用户明确要求时翻译。指定的输出语言与原文不同且未说明是否翻译时，无须固定追问：依据用户输入自动决定新增文字的语言，所给原文保持原样。
- **按文字调整版面：** 依实际文字长度调整字号层级、换行、分栏与页数，不靠缩到难以阅读或裁切来塞入内容。
- **字体兼容：** 选用当前环境可用且覆盖目标文字的字体，避免缺字与伪造字形。本 Skill 提到的宋体、黑体等气质，在其他文字中换用相近的衬线或无衬线字体。
- **阅读方向：** 阿拉伯文、希伯来文等从右到左文字须调整对齐、阅读顺序与时间轴、流程方向；混排时数字、拉丁词与标点保持正确。仅在文字适用且内容需要时使用竖排。
- **适用范围：** 本节约束演示内容与版面。版式或“简短说明”类建议不授权删减、压缩用户原文；原文与可核查史实或本 Skill 的史实边界冲突时，指出问题，经用户确认后才修改。
- **换语言不换风格：** 色彩、材质、纹理、光泽、层次、格调与意境保持本 Skill 的设计语言。示例图中的中文只是示例，不得照抄，也不代表默认语言。
- **交付检查：** 检查缺字、错字、断行、标点与方向。图像生成对该文字渲染不可靠时，改用可编辑文本层；做不到时如实告知用户。
